## 2. 一处机理说反了：止住崩溃的是"测试折裁到训练支撑集"，不是缩尾（P0）

v4 §2.1 写："**对 X 做逐折 winsorize 之后，两者收敛到同一个值** —— 这才是干净的估计。" 为检验这句话，我把两个操作拆开做 2×2：

| | **测试折不裁剪** | **测试折裁到训练 [p1,p99]** |
|---|---|---|
| **训练折不缩尾** | ① **−2.68**（max\|残差\| 62.8） | ③ **+0.222**（6.0） |
| **训练折缩尾[1,99]** | ② **−10.99**（max\|残差\| 133.4） | ④ **+0.225**（6.1，v4 定稿） |

**结论和 v4 相反**：

1. 只缩尾训练折、不裁剪测试折（②），结果**比什么都不做更差**（−2.68 → **−10.99**）。因为缩尾把训练 std 压得更小（6.5 → 更小），测试折那个 12596 被放大得**更狠**。
2. 完全不缩尾、只把测试折裁到训练 min-max（③），直接得到 **+0.222**——和 v4 的点估计一样。
3. 所以**唯一起作用的操作是"把测试折的 X 限制在训练折支撑集内"**，缩尾只是它的一个更温和的版本；三种"稳健预处理"（1–99 / 5–95 / 秩-正态）本质是**同一个操作**，不是三个独立证据。

**为什么必须改**：如果评委按 §2.1 的文字去复现"winsorize 让两者收敛"，会得到 −10.99，和你们差 11 个单位——比前三轮任何一次都难看。而且这个 2×2 里 **② 是一个极好的对照实验**，它恰好证明"缩尾不是原因"，写进论文是加分项，不是减分项。

**改法（三句话）**：
- §2.1 改成："单行的 12596 会让**任何**用折内统计量标准化的模型爆炸；唯一的止血办法是**把测试样本的取值限制在训练支撑集内**。缩尾、min-max 裁剪、秩变换都是这一件事的不同实现。"
- `protocol.py` 的 docstring 补一句："`Xte` 必须用 `Xtr` 的分位点裁剪；**只缩尾训练折不裁测试折会让结果更差（−10.99）**"。
- 加一条**有效域声明**（这也是一条真正的贡献）：模型的预测只对"每个化合物都落在训练范围内"的样品成立；超出范围的一律被截断，属于外推受限，不能声称可信。

> 顺带一个口径小问题：附录 C 的 `clip_eval` 用**全样本** `y.min()/y.max()` 裁剪预测，是轻微的测试集信息使用。我实测全样本裁剪与折内裁剪**结果完全相同（0.223 vs 0.223）**，所以不影响结论，但写成折内更干净——审稿人会看这一行。

## 3. "增量 +0.070" 高估了 70%（P1）

§2.3 用"纯风格 OOF R² = 0.153"当基线，得出"化合物超出风格 +0.070，43/50 为正"。问题是这个基线**本身是个有噪声的估计**：22 个风格里有 `Faro`(3)、`Brut`(4)，折内组均值极不稳定。用同一套 CV、同样正则化的 **one-hot Ridge** 做基线才是公平比较：

| 模型（同 CV、同 α 网格） | 总 R² | 中位 | 层内 R² |
|---|---|---|---|
| 化合物（v4 协议） | +0.226 | +0.160 | −0.131 |
| **纯风格 one-hot Ridge（公平基线）** | **+0.185** | +0.104 | −0.195 |
| 化合物 + 风格 | +0.227 | +0.160 | −0.128 |

→ **增量 = +0.041（36/50）**，不是 +0.070（43/50）。而且 **chem+style = 0.227 ≈ chem 单独 0.226**：加上风格几乎不涨。

这个结果其实**更漂亮**，因为它是对称的：
> 化合物能解释 22.6%，风格能解释 18.5%；**两者高度重叠——化合物已经包含了风格信息，风格在化合物之外几乎不剩增量（+0.001）**。

建议 §2.3 把基线换成 one-hot Ridge，同时报两个基线（组均值 0.153 / one-hot 0.185）并说明差异来源。数字从 0.070 改成 0.040，结论方向不变（增量真实但很小），但**不会被一句"你的基线没调参"推翻**。

## 4. "35 可达 / 15 不可归因"：计数稳，名单不稳（P1）

这是 v4 现在最常被重复的数字（摘要、§4.2、§5.2、§10.2 清单），所以值得单独查。三档缩尾各跑一遍 35 次 bootstrap：

| 缩尾档 | 可达 | 不可归因 |
|---|---|---|
| 1–99 | **35** | 15 |
| 5–95 | **36** | 14 |
| 10–90 | **35** | 15 |

**计数很稳，但成员会换**：

```
三档一致可达 32 维 | 三档一致不可达 11 维 | 边界翻转 7 维
翻转名单：A_malt_grain, F_malt_grain, A_esters_all,
          A_esters_fruity, F_esters_fruity, F_esters_isoaa, dms
```

也就是说 `dms` 在 1–99 下不可归因、在 5–95 下可能变成可达；`A_esters_fruity` 反之。**§5.2 的门控是按名单硬编码的，等于让 7 个维度的 Top-3 报不报由一个缩尾参数决定**——这和 §2.4 已经被你们否掉的"T1 就是这几个"是同一类问题，只是换了个位置。

**改法**：把门控从"CI 下界 > 0"改成"**稳定性频率 ≥ 0.8**"（在 bootstrap × 3 档缩尾的 3000 次里，CI 下界 > 0 的比例），然后报 **32 可达 / 11 不可归因 / 7 边界**。边界维同时给 Top-3 和 null，并注明"该维度处于可归因边界"。这样"35"这个数就不必出现在摘要里。
