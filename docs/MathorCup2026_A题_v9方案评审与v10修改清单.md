## 1. P0-1：分级表的形状量的是**真值**，不是**交付表**

### 1.1 先把三种装箱口径都算出来

### 1.2 这个错在哪

§4.1.3 第一步的表写：

> 分位数 7 箱（v7 主表）｜0 档占比 **14.6%**｜6 档占比 **14.4%**｜平均等级 **2.99**｜像不像评分表 ✅

**这三个数在数学上是必然的**：按 1/7 分位切真值，每档当然各约 14.3%、均值当然是 3.0。它与你模型的预测**完全无关**——哪怕模型是随机的，这张表的真值一栏也长这样。

而交付表里装的是**预测值**。按你写的规则（切点取自真值）去装，预测的等级分布是：

```
0 档 4.2%   1 档 4.6%   2 档 9.6%   3 档 23.8%   4 档 33.0%   5 档 20.7%   6 档 4.1%   均值 3.55
```

**两端各只有 4%，中间两档吃掉 57%。** 这不是"像 0–6 评分表"，这是**一个被正则化压向中心的预测分布**——完全符合 §2.1 对 Ridge 收缩的描述，但它跟 §4.1.3 承诺的形状正好相反。

> **顺带一个可以自查的旁证**：这张表里 min-max 那行的 `24.4% / 0.8% / 1.61` **只有用真值才能对上**（预测是 `11.8% / 0.0% / 1.61`）。所以要么这张表报的是真值（→ 它没回答"交付表长什么样"），要么它报的是预测（→ min-max 那行数值就是错的）。**两种读法必有一错**，而根因都是同一件：表头没写"这些占比统计的是谁的等级"。

要让交付表真的每档各 1/7，切点**必须取自预测分布**（第二行）：`14.4% / 14.4% / 3.00`。这条路是真能部署的——切点用**训练集 OOF 预测**的 1/7 分位定，套到新样本上，不碰测试批。

> **一句话**：§4.1.3 用"真值的等级分布"论证"交付表的形状"，而 v9 实际算 κ/命中率时用的是第三种（各自自身分位）。**三种口径各说一件事，文档把它们当成了一件。**

### 1.3 连带后果一：κ 的对比是两种装箱口径的产物

同一张表里，`0.3286`（分位数）只有用**预测自身分位**才能复现（我得 0.3406）；`0.4676`（min-max 的 exact）只有用**真值 min/max 同时作用于两者**才能复现（我得 0.4642）。也就是说：

**两个操作，一张表，然后比大小。** 统一到同一口径（切点取真值）后：

### 1.4 连带后果二：`+54% / +41%` 的"相对提升"也要改

§4.3 说"分位数 7 箱的 0.227/0.540 相对随机基线的提升（+54%/+41%）才反映真实能力"，而 min-max 的 0.468/0.904 是"虚高"。按统一口径重算：

| | exact | 随机基线 | 相对提升 | ±1 | 随机基线 | 相对提升 |

分位数仍然略高（39 vs 33、40 vs 23），但**不是 54 vs 22、41 vs 9**。差 6–17 个百分点，而维间 sd 是 0.1 量级 → **两者在等级命中上不可分辨**。

### 1.5 那主表还要不要换？——要，但理由只剩一条

**换的理由不是 κ，是形状**：min-max 下真值侧 0 档 24.4%、6 档仅 0.8%，而**交付侧更极端——0 档 11.8%、6 档 0.0%**（预测被收缩到中段，永远够不到 6）。**一份"0–6 评分表"里没有任何一个 6 分，这作为交付物本身就不合格。** 这条理由结实、可复现、不依赖任何统计口径，而且和 §4.1.3 第三步（刻度本身就是 0…6 七级）互相印证。

**建议的最终处置（三句话）**：

1. **交付表用"OOF 预测分布"的 1/7 分位定切点**（部署可得），表内每档 ≈14.4%、均值 3.00——与承诺一致，且这次真的对上了。

3. **删掉"分位数在有序距离上更合理"**，把换映射的理由收回到"形状 + 刻度七级"。

## 5. 建议新增的两条断言

**#22 交付表形状必须由预测等级算出（现在跑会红，红了才对）**

```python
# 交付表口径：切点取预测分布的 1/7 分位（部署可得）→ 表内每档 ≈1/7、均值 ≈3.0
def grade_deliver(p):
    c = np.quantile(p, np.linspace(0, 1, 8)[1:-1])
    return np.digitize(p, c)

g = [grade_deliver(P[:, j]) for j in range(50)]
share_0 = np.mean([(x == 0).mean() for x in g])      # 交付表，不是真值
share_6 = np.mean([(x == 6).mean() for x in g])
mean_g  = np.mean([x.mean() for x in g])
assert 0.12 < share_0 < 0.17 and 0.12 < share_6 < 0.17, (share_0, share_6)
assert 2.9 < mean_g < 3.1, mean_g

# 一致性指标口径：切点只能有一套，取自真值；与交付表分开算，不得互相顶替
def grade_eval(y, p):
    c = np.quantile(y, np.linspace(0, 1, 8)[1:-1])
    return np.digitize(y, c), np.digitize(p, c)
```

> 这条断言的意义：它把"报的是真值分布还是预测分布"变成一行可执行检查。**v9 会失败**，因为文档写 14.6/14.4/2.99——那是真值的分布，而交付表按真值切点装出来是 **4.2/4.1/3.55**。若你最终选择"交付表也按真值切点"（§1.5 的另一条路），把边界改成 `0.03 < share_0 < 0.06`、`3.4 < mean_g < 3.7`；**两条路都行，但不能一边写 14.6 一边按真值切点装箱**。

## 8. 写在最后

v9 把四个 P0 全部改到了，而且**每一条都自己算过**——这是八轮里第一次"评审的具体错误比被评审的还少"。剩下的两个 P0 形态也变了：

- 一个是**量错了对象**（报真值的分布，论证交付表的形状）；
- 一个是**量错了维度**（把"谁排第一"当成可报的事实，而它是抖的）。

它们都不是算错，是**在把一个统计量翻译成一句人话时，主语换了**。§4.3 那句"分位数在有序距离上更合理"尤其典型：数字没错，是**两个数字来自两套口径**。

这也解释了为什么断言 #20 有效但不够——它只检查"表内分项能否加出均值"，**检查不了"这个均值的主语是谁"**。所以这一轮我建议的两条断言都往"主语"上加：`#22` 问"这个 14.6% 是预测的还是真值的"，`#23` 问"这个第 1 名是不是抖的"。

能在初赛前把这两类问题清掉，剩下的就只是排版了。
